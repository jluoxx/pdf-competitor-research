# All Document - File Viewer：买量／自然用户与广告风险专项

包名：`com.alldocument.fileviewer.tools`；versionName=1.0 / versionCode=11。base SHA-256：`7eda322286a3ecdaf7ab054db02b4e2d66a05c5fb5d329e2f9d08d0d7178376d`。

## 结论先看

**有在线参数控制自然与非自然来源的广告差异，而且不是单纯的自然量开关。** 已还原链路：归因融合结果 → 来源与环境风险检查 → 内部org分组 → 逐场景广告限制。自然来源会进入受限分组；非自然来源也必须满足相关检查，才能脱离该组。因此“自然用户少广告，符合条件的买量用户进入更多广告流程”有代码及在线值支撑；“所有买量用户都展示、自然用户完全无广告”不成立。

**存在明显值得核查的广告风险组合**：应用抽屉点图标前的插屏流程、使用第三方应用后回到桌面的插屏调用，以及按同一风险分组改变部分图标和设置入口的隐藏行为。前两项属于优先核查的打断式广告风险；后一组合具有差异展示能力，但不能仅凭静态代码证明其目的就是躲避审核。

## 2. 归因是怎样传到广告判断的

### 2.1 自然与非自然来源判定

`jh0`中存在Install Referrer和第三方归因融合逻辑；融合模型`el5`包含organic、network、campaign等字段。`el5.i()`对organic字符串与`Organic`进行忽略大小写的相等比较。

`q77.e`合并归因结果流`jh0.J()`和在线配置流`scd.e()`，随后`q77$e$a.b`把网络、campaign以及解码后的限制参数交给`b87`。来源检测器`bq6`监听融合归因结果，编号为3。

来源检测器的关键分支已被REA和字节码交叉核对：

```text
没有融合归因结果 → UNKNOWN
organic == Organic → RSK，说明为illegal-source
非自然来源：
    ccsulso为空／缺失／解析失败 → 空关键词表 → SAFE
    关键词表非空且campaign包含任一关键词 → SAFE
    否则 → RSK，说明为illegal-camp
```

这里的`RSK`是该应用SDK内部枚举，不代表自然用户真的存在欺诈或安全风险。`ccsulso`筛选的是campaign字符串，不能误写成网络平台白名单。`Non-Organic`也只是非自然归因标签，不独立证明发生过付费投放。

证据：[REA读取bq6.d](acquisition_risk/acq_01.java.txt)、[bq6解码字节码](acquisition_risk/bq6.txt)、[Craft交叉读取](acquisition_risk/method_01.craft.txt)、[融合模型](acquisition_risk/el5.txt)、[归因融合](acquisition_risk/jh0.txt)、[配置与归因连接](acquisition_risk/q77$e$a.txt)。

### 2.2 内部org比自然归因范围更大

`q77.i`确实把`q77$a`作为`af1`回调注入广告控制器。`q77$a.b()`是场景判定器读取的org状态来源，其逻辑可概括为：

```text
details为空 → true
没有任何启用的条件，且有编号3的来源结果 → 来源状态 != SAFE
其余情况 → 汇总风险状态 != SAFE
```

所以未获得结果、结果未知、自然来源或启用的其他条件未通过，都可能使org=true；不能把它直接等同于归因平台的isOrganic。

`b87.r`只汇总已启用的检查：有RSK则汇总为RSK；已启用检查全部SAFE且非空才为SAFE；其他情况为UNKNOWN。本次启用集合为1/2/3，故非自然来源也可能因为ADB或时间条件被划进受限组。

|条件|证据与边界|
|---|---|
|1：ADB|`ve$a$a.emit`读取adb_enabled；值=1写RSK，否则SAFE；本次启用|
|2：系统时间|监听auto_time、手动设置时间／时区，结合时间变化条件处理；本次启用，但没有测任何设备是否命中|
|3：来源／campaign|自然来源RSK，非自然来源按上述匹配规则；本次启用|
|4：包安装检查|包内有PackageManager及包变化监听；本次未启用。虽然limit_package含org.wireshark.android，不能说当前正在检查该包|
|84：测试环境检查|包内t15类包含Firebase Test Lab相关读取，但本链路的b87$a初始注册列表只有1/2/3/4，且当前启用集合也没有84；不认定当前已检测审核／Test Lab环境|

证据：[org回调](acquisition_risk/q77$a.txt)、[回调注入](acquisition_risk/q77.txt)、[Craft方法原始指令](acquisition_risk/method_00.craft.txt)、[枚举SAFE/RSK/UNKNOWN](acquisition_risk/p0b.txt)、[汇总规则](acquisition_risk/b87.txt)、[ADB检查](acquisition_risk/ve$a$a.txt)、[注册列表](acquisition_risk/b87$a.txt)、[条件打包解码](online_limit_condition_decoded.json)。

### 2.3 dly是另一条时间／首日限制，不是买量判定

`q77$a.c()`读取`first_time_niuma`，`gu.a()`首次写当前时间。`q77$a.e()`在该时间缺失／异常小，或首启日期与当天DAY_OF_YEAR相同时返回true。基本判定器在此状态下检查dly<0；时间判定器把正dly乘1000，与距首启的时长比较。

因此`23000045.dly=1`是这层首启后1秒门槛，不能解释成安装一天后才展示，也不能用它证明规避审核。`44000036.dly=-1`则还受首日状态拦截。

证据：[首启写入](acquisition_risk/gu.txt)、[首日判断](acquisition_risk/q77$a.txt)、[字段解析](m050_bq7$b$a.a.java.txt)。

## 4. 哪些可能违规，哪些只能说可疑

本轮已实际读取Google Play官方政策，保存HTML、正文和抓取时间。以下是根据政策与代码作出的风险评估，不是Google的处罚结论。

1. **打断用户打开应用／回到桌面的插屏：高风险。** 官方禁止在用户选择其他操作时突然出现全屏插屏，以及干扰其他应用和设备操作的广告。23000045与23000046应优先验证触发时机、广告是否全屏、是否明确可关闭、目标动作是否被阻断。来源：[Ads](https://support.google.com/googleplay/android-developer/answer/9857753?hl=en)。
2. **按环境和归因改变可见入口、压制广告：具有规避审核的可疑组合，但动机未证实。** 在线条件能把自然来源、ADB等状态纳入受限分组，且同一组影响广告与设置／图标隐藏。官方禁止审核规避、未披露的核心功能差异和远程激活的隐蔽功能；但常规反作弊或广告分层本身不能直接等同于审核规避。仍缺商店完整披露核对、实际人群UI对照、审核环境差异运行证据。来源：[Deceptive Behavior，尤其Behavior Transparency](https://support.google.com/googleplay/android-developer/answer/17006354?hl=en)。
3. **隐藏设置／图标及重设桌面：需核查知情同意与恢复方式。** 官方要求用户知情同意地改变相关设备设置，并可方便恢复；本次只证明控制与判断链，未观察到真实设备设置变化或用户协议流程。来源同上。

Launcher桌面本身可以是该App的界面，**不能因为广告出现在桌面就自动判成应用外广告**。重点是是否在用户没有预期的操作点打断正常使用、干扰其他App或系统操作，以及是否透明披露。

以下尚无足够证据，不能认定：自动点击广告／伪造曝光、强制跳转商店、假关闭按钮、无法关闭超过15秒、锁屏广告已启用、后台覆盖其他App、检测到审核身份后藏广告。不存在这些结论不代表功能不存在，而是本轮未观察到足够证据。

政策原文证据：[Ads正文](acquisition_risk/policy/ads.txt)、[Deceptive Behavior正文](acquisition_risk/policy/deceptive.txt)、[抓取记录](acquisition_risk/policy/fetch_audit.json)。
